# 1. Requerimiento de negocio

En el flujo del perfil **usuario (Sanidad)**:

`Perfil → Historial de Requerimiento (Screen 12) → "Por Liberar X de Y" → Liberar Requerimiento (Screen 13)`

Cuando un requerimiento tiene **2 lotes por liberar**, el usuario registra una liberación con papel y
sobre (ej. **60 + 20**) sobre una cantidad pedida de **140** millares. Al presionar **Guardar liberación**,
la suma `papel + sobre` debe **descontarse** de la cantidad pedida: `140 − 60 − 20 = 60`. Cuando el usuario
vuelve a presionar **"Por Liberar 1 de 2"** y entra de nuevo a la pantalla de liberación, el campo
**Cantidad (millares)** debe mostrar **60** (el pendiente), no los 140 iniciales.

# 2. Solución implementada

## 2.1 Reglas de negocio aplicadas

| # | Regla |
|---|---|
| 1 | Pendiente = `cantidad pedida − Σ(papel + sobre)` de las liberaciones ya registradas (mínimo 0) |
| 2 | El campo `Cantidad (millares)` (solo lectura) muestra el **pendiente**, no el total pedido |
| 3 | Defaults de papel/sobre = **restante por presentación** (ej. papel `100−60=40`, sobre `40−20=20`) |
| 4 | Validación: bloquea "Guardar liberación" si `papel + sobre > pendiente`; exige `papel + sobre > 0` |
| 5 | Pendiente 0 → muestra 0 y bloquea Guardar con aviso |
| 6 | `cantidadLiberada` persistida = `papel + sobre` de ESA liberación (coherente con RF-165) |
