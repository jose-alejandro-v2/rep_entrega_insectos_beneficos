# HITO-016 — Docker del sistema + creación de programación todos los días + TZ fix

## Estado

**IMPLEMENTADO — verificado y comiteado** — 2026-09-09. Backend dockerizado por completo
(docker-compose proyecto `repo_registro_insectos_beneficos`: postgres:16 + imagen backend
`repo_registro_insectos_beneficos-backend` en `:6113` + nginx proxy `:8080` → `:6113`), corriendo
desde BD limpia con Flyway V1-V17. Creación de programación disponible **cualquier día** (el PUT
inicial del flujo crear envía `esCreacionInicial:true` y omite la restricción L/J). UX: al entrar a
"Nuevo" la tabla del mes se muestra **inmediatamente**, habilitada para digitar, sin esperar a
seleccionar especie. Zona horaria del contenedor backend en `America/Lima`. Versión **1.10.0** /
versionCode 13.

## Alcance implementado

### Docker (infraestructura del sistema)

- **`docker-compose.yml`** (proyecto `name: repo_registro_insectos_beneficos`): 3 services
  - `postgres` (postgres:16, credenciales de dev, healthcheck `pg_isready`, volumen `pg_data`).
  - `backend` (build `./backend`, depende de postgres healthy, `TZ: America/Lima`, puerto 6113,
    volumen `uploads_data` → `/app/uploads`).
  - `nginx` (nginx:1.27-alpine, `./nginx/nginx.conf` montado ro, puerto 8080 → 80).
- **`backend/Dockerfile`** multi-stage: build `maven:3.9-eclipse-temurin-17` (package `-DskipTests`,
  los tests usan Testcontainers y no tienen acceso al daemon Docker dentro del build) → runtime
  `eclipse-temurin:17-jre` con `ENV TZ=America/Lima` y `ENTRYPOINT
  ["java", "-Duser.timezone=America/Lima", "-jar", "quarkus-app/quarkus-run.jar"]`.
- **`backend/.dockerignore`**: excluye `target/` y artefactos del build.
- **`nginx/nginx.conf`**: proxy `server_name _` en `:80` → `http://backend:6113`.

### Backend — creación disponible todos los días

- **`UpdateProgramacionRequest.java`**: nuevo campo `Boolean esCreacionInicial = false`.
- **`ProgramacionService.updateProgramacion()`**: `verificarDiaEdicion()` se omite **solo** cuando
  `esCreacionInicial == true` (volcado inicial del flujo crear). La edición de una programación
  existente **sigue restringida** a Lunes/Jueves (RF-147/148).
- **`ProgramacionResourceTest`**: nuevo test determinístico `testPutConEsCreacionInicial_permiteVolcadoInicialCualquierDia`
  — POST (anio 2096, mes 3, especie 1) → PUT con `esCreacionInicial:true` → **200 sin importar el día**.

### Mobile — tabla visible al entrar a "Nuevo" + creación todos los días

`ProgramacionEdicionScreen.tsx` (modo crear):

- **Tabla al montar**: `filas` se inicializan con `generarFilasVacias(anio, mes)` (los params vienen
  del listado) → al entrar a "Nuevo" la tabla del mes aparece habilitada de inmediato, sin
  seleccionar especie.
- **`cambiarPeriodo`** (modo crear): regenera las filas vacías del mes seleccionado (antes las
  limpiaba a `[]`, ocultando la tabla).
- **`cambiarEspecie`** (modo crear): solo setea `especieId`; ya **no** regenera filas (no borra lo
  digitado). La especie solo habilita "Enviar stock".
- **`puedeEditar`**: en crear siempre `true` (tabla editable cualquier día).
- **`enviarStockCrear`**: el PUT envía `esCreacionInicial:true`.
- Se eliminan el aviso "La creación solo está permitida los lunes y jueves…" y el bloqueo del botón
  por día; el aviso de edición de `renderTabla` queda acotado a `modo === 'editar'`.

`ApiClient.ts`:

- `ActualizarProgramacionRequest` + campo `esCreacionInicial?: boolean`.

### Zona horaria (TZ fix)

- El backend en contenedor corría la JVM en UTC; el mobile usa hora Perú (UTC-5) → disparidad de día
  desde las 19:00. Corregido con `ENV TZ` + `-Duser.timezone=America/Lima` en `Dockerfile`/
  `docker-compose.yml`.

## Incidentes documentados (Ley 5)

### 1. Fix pre-existente: package de `DespachoDto.java`

`backend/src/main/java/pe/sistema/insectosbeneficos/despachos/dto/DespachoDto.java` estaba en
`pe.sistema.insectosbeneficos` (error de escritura "insectosbeneficos" commiteado desde HITO-015);
rompía el build limpio (mvn package). Corregido el `package` a
`pe.sistema.insectosbeneficos.despachos.dto`.

### 2. Tests catálogo vs seeds V7/V9 pendientes del usuario (Ley 5)

`V7__seed_catalogos.sql` añadió 34 lotes (total 157→191) y `V9__seed_catalogos_requerimientos.sql`
pasó de UPPER a Title Case (`FLORACIÓN Y CUAJA`→`Floración y Cuaja`, etc.). Los tests esperaban los
valores antiguos → `CatalogoResourceTest.testGetLotes` (157 vs 191) y
`CatalogoRequerimientoResourceTest.testGetEtapasFenologicas/testGetPlagas` fallaban.
**Fix:** `CatalogoResourceTest` → 191; `CatalogoRequerimientoResourceTest` → nombres en Title Case.

### 3. CumplimientoProgramacionResourceTest — colisión de periodo + bug jsonPath (Ley 5)

Los 3 tests de la clase creaban programación en el **mismo** periodo 2026/9 → al compartir BD
Testcontainers el 2º y 3º POST daban 409 `PROGRAMACION_YA_EXISTE`. Además `detalles.detalles[0].id`
es path inexistente (debe ser `detalles[0].id`) → NPE al extraer `detalleId`.
**Fix:** periodos únicos 2026/9, 2026/10, 2026/11 y path corregido a `detalles[0].id`.

### 4. Colisión ProgramacionResourceTest 2098/5 (Ley 5)

`testListProgramacionesReturnsMobileContractFields` y `testCrearProgramacion_duplicado...` compartían
2098/5 → según el orden de ejecución uno caía en 409. **Fix:** el primero usa 2095/2 (único).

### 5. Lint mobile pre-existente (Ley 5)

`mobile/__tests__/flows/login.e2e.test.tsx:147` tenía `let tree` sin usar (commiteado en v1.9.0) →
`npm run lint` → 1 error. **Fix:** se eliminó la variable no usada (0 errors, 11 warnings de `token.ts` esperados).
