## 1. Objetivo del HITO

Aplicar el procedimiento de `docs_implementacion/LOGIN_MODELO_REUTILIZABLE.md` con criterio
adaptativo (validado por el usuario, ADR-A003): **login 3 pasos (rol→usuario→DNI)**, roles en
tabla con literales, URL runtime + SecureStore, axios con interceptores, `/api/v1` + OpenAPI,
y APK v2 con módulo nativo `react-native-keychain`.

## 2. Alcance

  migración de datos desde `perfil` + rollback documentado (H12).

  nuevo JWT), CRUD `/api/v1/usuarios`, claims `groups/rolId/nombre/dni/passwordResetRequired`

  Settings (URL runtime), Login 3 pasos (autocompleta 00000000), CambiarPassword (nuevo JWT),

- **Versión**: bump 1.1.0 + `versionHistory.js` + APK v2 release con keychain (Ley 3).
- **Docs**: ADR-A003 + reconciliación G-DOC-SYNC (AGENTS.md, README, orquestación §17.x/§25.1,
  01_especificacion RF-001/009/016/023/026/191 + §6 Roles, 02_plan §21, 03_tareas, 04_implementacion).

## 3. Decisiones de arquitectura rectoras

- **ADR-A003**: (1) tabla roles + FK; (2) literales con espacios en BD y `@RolesAllowed`;
  (3) login 3 pasos sin login de texto; (4) password **máx 8 dígitos** (mantiene ADR-A002, no
  `^\d{8}$`); (5) URL runtime + keychain + axios + ServerCheck + Settings; (6) `/api/v1` +
  OpenAPI; (7) sin Firebase. Supera parcialmente ADR-A002 (D-AUTH-1 UX login, D-AUTH-2
  representación de perfiles); conserva D-AUTH-3/4/5/6.
- **Protocolo de tiempos**: §17.x orquestación (timebox → cortar → diagnosticar → documentar →
  siguiente) y §25.1 (pipeline dev→auditor con solape). Se aplicó en los 2 builds de APK
  (INC-3 cortado a 12 min con diagnóstico; reintento warm 1.1.0 terminado en ~4 min).
